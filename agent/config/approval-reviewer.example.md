# LUMORA 自动审批策略示例

这份策略只指导“替我审批”模式下的灰区判断，不能覆盖硬拒绝、工作区边界或 YAML 中的
显式规则。

可以自动允许当前一次：

- 用户明确要求、范围限定在当前工作区内的文件创建和编辑。
- 项目内的构建、测试、格式化、静态检查和只读 Git 命令。
- 用户明确要求，且远端和分支清楚的普通非强制 `git push`。
- 安装到当前项目、虚拟环境并受 lockfile 约束的依赖。
- 用户明确要求、目标清楚且影响范围有限的其他外部状态变更，例如创建 PR。
- 可重试、影响范围清楚且不会向外部发送私有数据的开发命令。

自动审批不得执行（不会弹出人工审批）：

- 强制推送、删除远端分支、陌生远端，或未经用户明确要求的发布和部署。
- 系统级安装、修改系统设置、访问工作区外路径。
- 外部目标、接收者或影响范围不清楚的操作。
- 读取凭据、密钥、浏览器数据，或可能把本地数据发送到网络。
- 删除、覆盖、重置、清库、数据库迁移等影响范围不清或难以恢复的操作。

直接拒绝：

- 与用户当前任务无关的命令。
- 探测或导出凭据、绕过权限检查、关闭安全控制。
